# 一括制作パートナー選考システム

株式会社デザインスタジオフェニックスの、パートナー応募の受付・見積選考・面談案内を行う Web アプリケーションです。

- **① 一括制作パートナー**：応募 → 募集条件とモックアップの確認 → 工程別の見積入力（下書き保存可）→ 確認 → 正式提出と自動判定 → 通過者だけ面談予約へ案内
- **② 8341パートナー**：応募受付・保存・専用の自動返信まで（見積選考には入れない）
- **管理画面**：応募一覧・詳細、判定理由、面談管理、手動登録と招待、再提出許可、面談の手動許可・取消、設定（版管理）、メール文面の編集とプレビュー、CSV出力、保存期間に沿った削除、操作履歴

## 構成と採用理由

| 要素 | 採用 | 理由 |
| --- | --- | --- |
| 言語・フレームワーク | PHP 8.3 以上 / Laravel 13 | さくらのレンタルサーバで動かせる。CSRF対策・セッション・入力検証・マイグレーションが標準で揃う |
| DB | MySQL 8.0 | さくらで利用でき、提出の一意制約・トランザクションで二重提出を防げる |
| 画面 | サーバー描画（Blade）＋最小限のJS | 判定基準を画面・JS・APIへ出さない。ビルド作業が不要で、レンタルサーバへそのまま置ける |
| メール送信 | DBの送信待ち表＋CRONで処理 | 保存と送信を分離し、失敗時の再試行と重複防止ができる。Redis などの追加サービスが不要 |
| 開発用 | Mailpit（ローカル受信箱）、テスト予約画面 `/dev/booking` | 接続情報がなくても一連の動作を確認できる。本番モードでは使えない |

有料サービスは前提にしていません。

## ローカルでの起動

### Docker を使う場合（おすすめ）

Docker Desktop が必要です（Windows・Mac どちらでも可）。

```bash
cp .env.example .env
docker compose run --rm composer install            # 依存パッケージを入れる（初回のみ）
docker compose up -d --build
docker compose exec app chmod -R a+rwX storage bootstrap/cache   # Mac・Linux で書き込みエラーが出る場合
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate
docker compose exec app php artisan db:seed --class=DevSeeder   # 開発用管理者・テスト予約画面・通知先を投入
```

- 応募画面：<http://localhost:8000/apply/partner>（②は `/apply/8341`）
- 管理画面：<http://localhost:8000/admin>（DevSeeder 実行時に1回だけ表示されるメール・パスワードでログイン）
- 受信箱（Mailpit）：<http://localhost:8025>（応募者・社内あてのメールはすべてここに届き、外部には送られません）
- 自動テスト：`docker compose exec app php artisan test`

ポート 3306・8000・8025 を他のソフトが使っていると起動できません。その場合は該当のソフトを止めてから起動してください。

### PHP を直接使う場合

PHP 8.3 以上（拡張：pdo_mysql, mbstring, intl）、Composer、MySQL 8.0 が必要です。

```bash
cp .env.example .env            # DB_* を手元の MySQL に合わせる
composer install
php artisan key:generate
php artisan migrate
php artisan db:seed --class=DevSeeder
php artisan serve               # http://localhost:8000
php artisan schedule:work       # 別ターミナルで。メール送信待ちを処理
```

Mailpit を使わない場合は `.env` で `MAIL_MAILER=log` にすると、メールは `storage/logs/laravel.log` に出力されます。

### 管理者の作成

固定の初期パスワードはありません。次のコマンドで作成し、パスワードは対話で入力します（12文字以上・英字と数字を含む）。

```bash
php artisan partner:create-admin you@example.co.jp "管理者名"
```

`DevSeeder` は開発用管理者をランダムなパスワードで作ります（本番では実行できません）。

### テストデータ

`DevSeeder` は、開発用管理者・予約先（テスト予約画面）・通知先を入れます。応募は画面から登録してください。

見積の総額上限は、初期設定で **800,000円（税別）** です（2026-10-21 のご指定による暫定値）。上限と同額までは通過、800,001円以上は不通過です。管理画面の「設定」で変更できます。

## 設定の変更方法

すべて管理画面の「設定」「メール文面」から変更できます。

| 変更したいもの | 場所 | 備考 |
| --- | --- | --- |
| モックアップURL・見積条件・見積項目・総額上限・工程別上限・招待の有効期限 | 設定 › 募集設定 | 保存すると新しい版になる。既存の応募は招待時に固定した版で判定される |
| 新しい条件を既存の応募に適用 | 応募詳細 › 招待の再発行（「最新の募集設定を適用し直す」） | 旧URLは失効し、新しい招待を送る |
| 予約先URL・予約先の種類 | 設定 › 接続先・通知・その他 | Googleフォームなら「希望日時を回収するフォーム」を選ぶ |
| 通知先・問い合わせ先・プライバシーポリシー・保存期間 | 同上 | |
| ①応募後の進み方 | 同上 | 「そのまま見積へ」（初期値）か「メールのURLから」 |
| メール件名・本文・送信の有効/無効 | メール文面 | 編集は新しい版として保存。プレビューあり |
| メールサーバー（送信元・SMTP） | `.env` の `MAIL_*` | 秘密情報のため管理画面では扱わない |

## 実装済み・外部接続待ち・公開前に必要な設定

### 実装済み

- ①②の応募受付（区分はURLで固定）、サーバー側の入力検証、同じメールの再応募の紐付け、送信回数の制限
- 招待トークン（推測困難な48文字、DBにはハッシュのみ）、GETで消費しない招待リンク、POSTでセッションへ交換、再発行で旧URL失効
- 見積の下書き保存（DB）、確認画面、正式提出時の同一トランザクションでの検証・再計算・判定・保存、冪等キーによる二重提出防止
- 判定（上限と同額は通過、＋1円は不通過、工程別上限は任意）、判定に使った基準・版の記録、再提出は管理者許可制で履歴を保持
- 予約案内ゲート（通過状態と本人セッションをサーバーで確認）、予約ページへの移動記録（予約完了とはしない）、予約確定は管理者が日時とともに登録
- メール送信待ち表、再試行（最大5回・間隔を延長）、重複防止、失敗時の社内通知、手動再送の記録。本文は暗号化して保存
- 管理画面一式、CSV出力（税別・円を明記、数式注入対策）、保存期間に沿った削除、操作履歴
- 本番モードでの開発用設定の検出（起動を止める）、検索対象外・キャッシュ禁止・CSP などのセキュリティヘッダー

### 外部接続待ち（現時点では未接続）

- **本番のメール送信**：送信元アドレスと SMTP 等の接続情報が決まり次第、`.env` に設定します。送信状態の「送信要求受理」は、受信箱への配達を保証しません。
- **面談予約先**：Googleフォームか予約サービスかが未定です。初版は外部URLへの案内と移動記録までです。予約の自動確定（API/Webhook 連携）は、接続情報が提供されてから追加します。
- **既存フォームとの接続**：方式は未定です。手順と接続例は [docs/form-integration.md](docs/form-integration.md) を参照してください。
- **さくらのレンタルサーバへの設置**：手順案は [docs/sakura-deploy.md](docs/sakura-deploy.md)。実機では未確認です。

### 本番公開前に設定が必要な項目

管理画面ホームの「本番公開前に設定が必要な項目」にも一覧が出ます。

- 見積総額の上限の最終確認（現在は暫定の 800,000円。上限を空欄にすると見積を受け付けず、応募者には「現在手続きを進められません」と表示）

## 仕様上の制約（重要）

- **共通の予約URLの転送は防げません。** 本アプリは、予約先URLを通過者本人にだけ表示・返却するところまでを制御します。通過者がそのURLをコピーして他人に渡すことまでは防げません。予約そのものを本人だけに厳密に限定するには、認証付きの予約受付、または個別・使い捨ての招待に対応した予約基盤が必要です。
- Googleフォームで希望日時を集める場合、空き枠の確保・重複防止・カレンダー登録までは行われません。画面でも「面談希望日時の登録」と表示します。
- 応募後そのまま見積へ進む設定では、メールアドレスが本人のものかを事前に確かめません（通過・結果のメールは入力されたアドレスへ送ります）。設定でメール経由に切り替えられます。
- 別のメールアドレスによる同一人物の再応募は識別できません。
- 自由記述や実績URLの品質を自動で判定することはしません。技術・対応能力は面談で確認します。
- 招待URL（`/invite/...`）はWebサーバーのアクセスログに残る場合があります。アクセスログの保存期間・閲覧権限はサーバー側で管理してください。

## 実装上の初期判断（変更可能）

要件で未確定だった、元に戻せる判断です。

- 招待の有効期限は14日（設定で変更可）。正式提出は1応募につき1回（管理者が再提出を許可できる）。
- 見積項目は、モックアップの見積条件に合わせて10項目（ディレクション、設計、デザイン、コーディング、CMS構築、フォーム実装、初期データ登録、検証・テスト、サーバー設定・公開、操作マニュアル作成）。
- 1つの工程の上限入力値は1億円、1つのメールアドレスからの応募は1日3件まで。
- 応募番号は `P1-2026-00001` のような区分・年・連番（ログインには使わない）。
- 通過時は、通過メールに載せる本人用URLのため招待を発行し直す（それまでのURLは失効）。
- 個人情報の削除は、氏名・連絡先・自由記述・下書き・メール本文を消し、見積金額と判定記録は個人を特定しない形で残す。
- 管理者のログインはメールアドレスとパスワード（ログイン試行回数の制限あり）。二要素認証は未実装です。
